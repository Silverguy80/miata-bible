# The Miata Bible rebuild

## Outcome 1: workshop-magazine app shell
- [ ] The app uses the confirmed Japanese workshop / enthusiast-magazine direction rather than the current generic prototype layout.
- [ ] The product remains branded as The Miata Bible.
- [ ] The app presents a manual rail, reading surface, and fitment/context rail on desktop, with a usable stacked/mobile layout.

## Outcome 2: all-generation Miata coverage
- [ ] Coverage includes NA, NB, NC, and ND with generation-aware facts, fitment labels, and source-linked imagery.
- [ ] Manual and parts filters distinguish applicable, conditional, and excluded generation coverage.

## Outcome 3: extensive organized repair manual
- [ ] The manual is structured as books, chapters, procedures, symptoms, systems, tools, parts, safety, verification, common mistakes, related procedures, and sources.
- [ ] The reader supports chapter navigation, search, generation filtering, procedure deep links, saved procedures, and print-friendly reading.
- [ ] Content is original and copyright-safe; it does not reproduce commercial factory/manual wording or diagrams.

## Outcome 4: garage, mods, budgets, and build history
- [ ] A user can define a Miata profile, add or replace upgrades, see budget deltas, and retain replaced parts in an append-only history.
- [ ] Build plans and named snapshots are supported for reliability, street, autocross, track, turbo support, and restoration paths.
- [ ] The user can export and restore a complete garage history.

## Outcome 5: cloud-save-ready persistence
- [ ] The app exposes explicit saving/offline/error state and never silently discards local changes.
- [ ] The persistence layer is isolated so managed authentication and cloud storage can be connected without rewriting feature components.

## Outcome 6: accessibility and quality
- [ ] Labels, landmarks, focus states, keyboard navigation, contrast, 200% zoom, and reduced-motion behavior are handled.
- [ ] Build and syntax checks pass before publication.
